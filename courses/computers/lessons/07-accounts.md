# 7. Accounts, permissions and updates

[Course home](../README.md) · [Curriculum](../CURRICULUM.md) · [Glossary](../GLOSSARY.md)

**Objective:** Recognise when a task needs permission and identify safer account habits.

An account identifies a user or a relationship with a service. Signing in to a computer does not necessarily sign in to every website. A permission determines which actions are allowed. Knowing a password or seeing an administrative prompt does not mean you are authorised to change the device.

Use unique passwords for different accounts and an appropriate password manager when available. Multifactor authentication adds a verification step. These measures reduce risk; they do not make an account impossible to misuse. Never approve an unexpected sign-in prompt or share recovery codes to complete a course exercise.

Updates can fix known security problems. Use the device owner's approved update process rather than an unsolicited message claiming urgent repair. Managed work or school computers may require an administrator's process. Do not disable protections or bypass a permission prompt.

We will reason about fictional situations. No real password entry, account creation, update installation or settings change is required.

## Practise

Choose a response to each invented situation:
1. A browser message says “Call this number now or lose all your files.”
2. A familiar application asks to install a new version on a shared work computer.
3. You receive an unexpected request to approve a sign-in.
4. Someone offers to troubleshoot if you send your password.

Write what you would verify and who is responsible for permission.

## Suggested reasoning

Do not trust the phone number supplied by the alarming message; seek help through a known route. Check the work computer's approved update process before allowing changes. Reject unexpected authentication approval and use the account provider's known support/security route if concerned. Do not send passwords; describe the problem without secrets. These are general decisions, not a complete incident-response procedure.

## Try a new situation

A task can be completed by reading a document, but a helper asks for administrator access. What narrower action would you request, and who should decide whether access is granted?
